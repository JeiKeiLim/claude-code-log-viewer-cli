### Critical Issue: CLI Smoke Testing Gap

**Problem:** After implementing Story 7.6 (`cclv -u`), the agent did not actually run the command against real credentials. A credential parsing bug existed that was only discovered when the user manually tested.

**Root Cause:**
- Agent followed story tasks literally (write code, write tests, verify coverage)
- Story did not include explicit "smoke test against real environment" task
- Unit tests used mocks, missing real integration verification

**Impact:** Bug shipped that could have been caught with a simple `cclv -u` invocation.

**Lesson:** CLI features require "eat your own dog food" validation - actually running the command, not just testing with mocks.

### Code Review Effectiveness

Code review caught issues in every single story:
- Story 7.2: Missing `isTimeoutError()` helper, empty token test
- Story 7.3: Missing composite style function, dead code
- Story 7.4: Height allocation in 4 handlers, duplicate style injection code
- Story 7.5: Lowercase 'r' handling, tick scheduling edge cases
- Story 7.7: "Unknown" vs "Usage unavailable" text, context.Canceled handling

**Conclusion:** Code review process is working. Continue rigorous review.

## Key Lessons Learned

1. **CLI features need smoke testing** - Unit tests with mocks are not sufficient; must run actual command
2. **TUI integration is fragile** - Code review catches what unit tests miss
3. **Soft-fail pattern is proven** - Standard approach for external service integrations
4. **Story tasks must be explicit** - If smoke testing isn't in the task list, agent won't do it
5. **Code review is essential** - Caught real issues in 100% of stories
